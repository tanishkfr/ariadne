## 1. V1.3 status

**READY FOR PRIVATE USE — VERIFIED local creative operations; EXTERNALLY
UNVERIFIED provider automation.** Builder OS now carries approved design intent
through implementation mapping, rendered visual evidence, drift classification

This is not a claim that Cursor, ACP, a provider subagent, social publishing,
production deployment or a complete V1.3 external-provider build ran.

## 3. Human Intervention Budget improvements

**BUILT and VERIFIED.** Runtime state distinguishes necessary human authority,
valuable creative choices, avoidable interruptions, unacceptable system
maintenance and prevented interruptions. It records status and evidence,
deduplicates repeated prompts and resolves external launch actions when their
return is ingested. Existing G1–G5 decisions remain human-owned.

The integrated lifecycle positive control records required authority while
reporting zero avoidable and zero maintenance interruptions. Invalid
classifications are rejected.

## 4. Creative Director Loop improvements

**BUILT and VERIFIED.** The new creative-review method begins only after real
rendered or observed evidence. It judges thesis, distinctiveness, memorability,
craft, interaction, narrative, implementation quality, fidelity, portfolio
value and genericness; each judgement cites evidence IDs. It then preserves the
strongest aspect, weakest aspect, biggest risk, one highest-value improvement,
iteration decision and a do-not-change boundary.

It is an internal quality loop, not independent S5 and not gate approval.

## 5. Design → Implementation Traceability improvements

**BUILT and VERIFIED.** After G1, Builder OS derives traceable requirements
from `DESIGN.md`, `HANDOFF.md`, `PROJECT.md` and `AGENTS.md`. Each requirement
retains the canonical project source, exact text anchor and SHA-256. An
implementation event must identify the real source path, anchor, status and
summary. Source or approved-document drift makes the evidence stale.

## 6. Visual QA improvements

**BUILT and VERIFIED locally.** The visual-QA method tests the actual thesis,
signature moment, responsive transformations and important interactions before
secondary polish. Evidence states are explicit: source inference is not a
render, a render is not an observed interaction, and `verified` requires an
earlier positive control. Unreachable states preserve an environmental blocker.

Signal Atlas was rendered and interacted with at 1280px, 768px and 375px. The
system found a real tablet-direction drift while keeping unavailable reduced-
motion behaviour unverified. This was not an independent S5 review.

## 7. Skill-selection improvements

**BUILT and VERIFIED.** V1.2's adaptive assessment now selects visual QA and
creative review where a post-G1 rendered project requires them. Social strategy
is selected only by an explicit social request. Selection, invocation,
completion and use remain separate states; adding a skill does not make it run.

## 8. Research/reference improvements

**BUILT and VERIFIED.** Social recommendations that claim documented or
observed platform behaviour require an inspected reference ID and checked date.
Inferred and speculative advice remains labelled. The design and social paths
reuse the V1.2 evidence ledger rather than creating another source registry.

## 9. Evidence/provenance improvements

**BUILT and VERIFIED.** Project evidence now retains:

`approved decision -> implementation anchor -> rendered/observed result -> drift judgement -> creative priority`

Artifacts are hashed; source anchors must still exist; stale artifacts fail.
S4B packets carry the current operations plan with source parity. S5 carries
none of it. Social artifacts and revisions retain their hashes and parent IDs.

## 10. Subagent recommendation

**IDEATED, not implemented.** Use limited subagents only for bounded independent
work with explicit inputs, output schema, parent, stop condition and failure
state. Good candidates are current-source comparison, targeted technical
investigation and evidence capture. Keep routing, gates, material creative
changes, credentials, publishing and S5 judgement with their existing owners.

OpenAI and Cursor document relevant current capabilities, but Cursor was
unavailable and no provider multi-agent run was performed. Multi-agent support
must remain an adapter option, not a core dependency.

## 11. Automated handoff recommendation

**BUILT transport; READY TO PROTOTYPE provider launch; EXTERNALLY UNVERIFIED.**
The durable contract remains the verified packet plus a unique return target.
Future ACP/headless automation may carry that same contract when authentication,
permissions, cancellation and recovery can be tested. It must not own workflow
semantics or silently approve a gate.

## 12. Document-transport improvements

**BUILT and VERIFIED.** S4B now receives the project creative-operations plan
and canonical visual-QA method. Its manifest and prompt contain one unique
`.builderos/returns/<packet-id>.md` target. Verification rejects a target that
escapes the project, does not match the packet ID, is missing/duplicated or is
paired with a stale creative-operations source. Retries never reuse a target.

When a provider writes the complete marked return there, `advance` ingests only
the current packet's file. Manual `ingest-return` remains recovery for a
provider that cannot write project files.

## 13. Social-media capability status

**BUILT and VERIFIED locally; publishing BLOCKED without explicit authority.**

platforms, gives three or more project-specific concepts, records timing as a
test, defines measurement/iteration, produces non-generic example copy and
keeps copy rough when voice evidence is absent. It neither posts nor connects
an account.

## 1. V1.2 status

**READY FOR PRIVATE USE.** The scoped creative-intelligence and evidence pass is
complete. Builder OS can now choose project-specific research and methods,
separate claims from observed evidence and downstream use, and block unsupported
creative claims before G1.

This is not a claim that Cursor executed, that a complete external build return
was observed, or that production deployment is ready. Those boundaries remain
externally unverified from V1.1.

## 2. Meaningful capabilities added

- One backward-compatible project-local creative evidence ledger for new runs.
- Reasoned research-depth selection: minimal, standard or deep.
- Project-specific capability selection with question, reason, inputs, output,
  and mandatory/optional status.
- Strict skill execution evidence and replay-based tamper detection.
- Found, inspected, inaccessible and downstream-used reference distinctions.
- Hashed retrieval/output/downstream artifacts with stale-evidence detection.
- Reference conflict, direction alternative, resource decision and exact
  downstream-decision records.
- Pre-G1 checks that cannot pass from expected prose alone.

## 3. Skill-selection improvements

The post-S1 assessment interprets novelty, uncertainty, visual dependence,
technical uncertainty, domain complexity, reference sensitivity, generic risk,
interaction complexity, asset uncertainty and motion dependence. It chooses
only relevant work from intake, technical research, reference analysis,
component research, motion, asset research, design direction, implementation
planning, QA and independent review.

Every method is retained as `recommended`, `invoked`, `completed`, `used`,
`skipped` or `failed`. Completion requires a prior invocation and a hashed
output; use requires a downstream artifact plus existing decision IDs. Directly
editing the JSON to remove the invocation is now detected by history replay.

## 4. Research improvements

Research begins from a project-specific question, reason and strategy. The
assessment chooses its depth without showing the classifier to the user. A
minimal Focus Timer fixture selected no reference, technical, component, motion
or asset pass and went directly from brief to design-direction context.

The S2 contract requires a source to be retrieved before a finding can be
Verified. Inaccessible sources carry a blocker and no observations. Research
can finish with an honest unresolved result; missing evidence cannot emit a
misleading S3 transition.

## 5. Reference improvements

A reference record contains its URL, inspection kind, actual capture artifact,
capture hash, direct observations, at most two transferable mechanisms, why it
matters, what may be borrowed and what must be rejected. Found-only and
inaccessible references cannot appear as influences in `DESIGN.md`.

The realistic Living Margins fixture actually loaded and inspected:

- `https://publicdomainreview.org/collections/` — visual hierarchy and adjacent
  provenance;
- `https://storycorps.org/stories/` — human fragment versus regular tile rhythm;
- `https://neal.fun/space-elevator/` — interaction exercised from its initial
  state to a visible 1513 m progress state.

All three captures live in that fixture's `.builderos/evidence` directory and
are hashed by its ledger. No observation was inferred from the URL alone.

## 6. Resource and dependency improvements

Resource events cover libraries, frameworks, browser APIs, fonts, icon sets,
asset/image sources, techniques, design tools and component primitives. Each
record requires:

- what the resource provides and why it fits;
- compatibility and licence evidence where relevant;
- implementation cost;
- at least one named alternative and rejection reason;
- whether it is necessary;
- a use, do-not-use or defer decision;
- at least one inspected source;
- an exact anchor in a hashed downstream artifact.

The technical fixture selected a platform capability and rejected a package
after comparing alternatives. It proves the decision contract, not current
package compatibility, version or licence facts. No dependency was installed or
approved.

## 7. Design-direction improvements

S3 now receives creative provenance when available and requires live retrieval
or visual evidence before describing a reference as inspected. Reference-
informed decisions follow:

`reference -> observation -> principle -> project decision -> implementation requirement`

The pre-G1 checker rejects a missing/generic thesis, missing tension, missing
signature or mobile equivalent, fewer than three project-specific rejections,
an incomplete ten-question G1 check, cosmetic alternatives, and unsupported
reference claims. Alternatives are required only when the assessment says they
would materially help.

Living Margins compared a continuous marginal trace with a retrieval-led
reading-room index. They differ in mechanism and visitor experience, not merely
palette. The controller then stopped at G1; no direction was self-approved.

## 8. Evidence and anti-fabrication improvements

The runtime now preserves the following distinctions:

| Domain | States that no longer collapse |
|---|---|
| Skill | recommended / invoked / completed / output used / skipped / failed |
| Reference | found / inspected / inaccessible / used by named decisions |
| Resource | evaluated / selected or rejected / anchored downstream |
| Provider | selected / execution observed or provider-reported / returned successfully |

Inspection, completion and downstream-use claims require separate artifacts and
hashes. Stale files, missing captures, uninspected sources, broken decision
anchors, hand-edited transitions and unevaluated library claims fail checks.
This does not make a local artifact impossible to forge; it prevents ordinary
workflow prose from proving its own execution and preserves the evidence class
for review.

## 9. Creative-memory improvements

The ledger survives fresh processes and continuation packets. It retains the
assessment, selected methods, source observations, conflicts, resource choices,
candidate/rejected directions and exact downstream decision anchors. S2 and S3
receive it when present; legacy projects without it remain readable and are
explicitly `legacy-untracked`.

Project documents remain canonical for active decisions. The ledger records
provenance and use; it does not grant a gate or replace `PROJECT.md`,
`DESIGN.md`, `HANDOFF.md` or `QA.md`.

## 10. Other meaningful features added

- Human-facing provider status now reports selected, executed and returned-
  successfully evidence separately. A verified preflight cannot imply that a
  provider ran.
- S2/S3 packet preparation carries current creative provenance and detects
  project or canonical source drift. S5 carries none of it, preserving review
  isolation.
- The Builder OS entry skill uses one progressively disclosed creative contract
  rather than exposing a matrix or adding a generic skill.
- Operations remain calm: the user sees the focused work chosen, useful
  findings, evidence gaps and next human decision.

## 14. Remaining friction

- Real visual inspection still depends on an available browser or equivalent
  retrieval tool; unavailable pages must remain inaccessible.
- A human still decides G1 and all later gates. This is deliberate authority,
  not automation debt.
- A custom run directory outside the project's parent cannot be rediscovered
  from only the project path; normal `$builderos start` uses the discoverable
  sibling location, while validation/custom operators must retain `--run-root`.
- The assessment is deterministic from its structured input but the initial
  interpretation remains model reasoning and needs more diverse real briefs.

**V1.1 status: READY.** Builder OS is ready for private real-project use and the
next live Cursor validation. This is a product-readiness decision, not a claim

The product now starts or resumes from ordinary language, explains the project

external handoff, carries partial work into a non-overwriting continuation,
accepts existing repositories without destructive migration, and gives a fresh
task enough durable context to continue without the old conversation.

## 2. System understanding

Builder OS is a provider-neutral creative-production workflow. Canonical
Markdown owns routing, gates, design, research, QA and project decisions. A thin
runtime discovers project state and prepares verified transport artifacts. Codex
normally performs reasoning work, an implementation provider performs the build,
and a fresh independent reviewer performs judgement. Humans retain creative,
dependency, acceptance, ship and publish authority.

The system works because four boundaries remain distinct:

1. canonical policy versus generated transport;
2. project decisions versus conversation history;
3. mechanical evidence versus independent judgement;
4. routine automation versus human gates.

## 4. Architecture and philosophy preserved

- `ROUTER.md`, `WORKFLOW.md`, mode definitions and gate meanings are unchanged.
- Canonical design, motion, asset, QA, research, evaluation, privacy and budget
  policies are unchanged.
- `templates/HANDOFF.md` remains the project-to-implementer contract; the added
  fields transport already-owned outcomes, content readiness and discretion.
- Generated packets, state, JSON views and operations logs are transport/runtime
  artifacts, not policy owners.
- No policy is copied permanently into a project repository.
- No gate can be granted by the runtime, skill, implementer or reviewer.
- No remote push, deployment, production change, credential access or package
  installation occurred.

## 5. Project intelligence and health

The runtime derives a briefing from `PROJECT.md`, `DESIGN.md`, `HANDOFF.md`,
`AGENTS.md`, `QA.md`, packet lineage, provider preflight, structured returns and
append-only project notes. It reports:

- full goal and mode;
- where work stopped in human language;
- approved direction and rejected-direction count;
- blocking/open questions, constraints and references;
- brief, research, direction, assets, dependencies, handoff, provider,
  implementation, QA and continuity health;
- completed implementation work and known issues when returned;
- durable decisions, risks, lessons and evidence gaps;
- one next action and exactly what is needed from the human.

It does not infer a gate, invent a provider result, turn a structural output into
a transcript, or classify externally unobserved behaviour as verified. Evidence
notes are explicitly `verified`, `reasonably-assumed`, `externally-unverified`
or `blocked`.

## 6. Automation and re-entry

The normal entry skill now:

1. discovers the single matching run or refuses ambiguity;
2. reads the current verified packet itself;
3. performs compatible reasoning in the same task;
4. records obvious project outputs structurally when no transcript exists;
5. prepares the next canonical boundary;
6. pauses only for a gate, material decision or external action.

G1 decision. It needed no prompt, packet, manifest, hash, transcript or run-path

## 7. Friction removed

- Manual prompt/template location.
- Manual packet concatenation and source parity comparison.
- Manual parent ID, continuation ID and transcript destination selection.
- Manual reconstruction of a returning project's goal and approved direction.
- Manual re-entry of routing already recorded in `HANDOFF.md`.
- Starting a large external task before provider preflight.
- Low-level retry knowledge after partial or blocked implementation.
- Destructive workarounds for adopting an existing repository.
- Shared self-test directories that made concurrent validation unreliable.

## 10. External return path

Every S4B provider receives the canonical marked return template. Builder OS:

- validates all required metadata and sections;
- preserves the Markdown report;
- derives a deterministic JSON view with the source SHA;
- keeps transcript evidence separate;
- creates a same-stage child for partial/blocked work;
- permits complete work to reach S5 only when mechanical QA exists;
- never converts provider self-report into independent review evidence.

The full path is negative-tested and synthetically exercised. A complete live
Cursor-to-Codex return is still externally unverified.

  directories.

- Adoption preserves every existing file and current behaviour, initialises Git
  only when missing, and creates only missing Builder OS entry documents after
  S1 resolves.

  they need a deliberate S4A refresh, not silent reinterpretation.

### Creative quality and learning

V1.1 did not rewrite the proven design or independent-review policies. Instead,
it made quality state harder to lose: the briefing carries the approved thesis,
rejected-direction count, references, unresolved risks, implementation drift
checks and QA state. Handoff readiness now rejects thesis or success-criteria
drift before implementation. The independent reviewer and human still decide
whether finished work is good enough.

Project learning is append-only and evidence-labelled. Builder OS can retain a
decision, rejected direction, risk, lesson, evidence gap or recovery event
without silently promoting one project's lesson into global policy. Global
learning remains the deliberate retrospective path.

## 15. Name assessment

**Decision: keep “Builder OS” as the internal V1.1 working name, but do not
launch it publicly under that name without a deliberate rename/clearance.**

The name is useful in the repository and changing it now would create broad,
high-risk migration work unrelated to reliability. It is weak as a public name:
multiple current products use BuilderOS, including a very similar AI-building
skills system at https://www.builder-os.dev/ and
https://github.com/BuildGreatProducts/builder-os. The name therefore has poor
distinctiveness and real confusion risk.

## Human intervention budget

`valuable`, `avoidable` or `unacceptable`, with pending, resolved, observed or
prevented status. The status projection reports creative decisions, valuable
choices, avoidable interruptions, system-maintenance interruptions, prevented

## Creative Director Loop and design trace

**BUILT and deterministically verified.** After G1, the controller derives
testable requirements from the locked thesis, signature moment, fixed handoff
decisions, responsive transformations and interaction principles. Each retains
its source path, exact anchor and SHA-256. A generated visual-QA plan orders
thesis/signature evidence before secondary polish.

Implementation events map those approved requirements to real source anchors.
Visual events distinguish `code-suggests`, `rendered`, `observed`, `verified`
and `unverified`; `verified` requires a prior rendered or observed positive
control. Drift is separately `approved`, `allowed`, `drift` or `unknown`.

The creative-review method judges ten project-quality dimensions from evidence
IDs, records the strongest and weakest aspects, names one highest-value
improvement, states whether iteration is justified, and protects what should
not change. It cannot update `DESIGN.md`, approve G3 or enter the isolated S5
context.

## Provider, subagent and automated-handoff recommendation

Current official capability pages inspected on 2026-08-23:

- [OpenAI latest-model guidance](https://developers.openai.com/api/docs/guides/latest-model)
  describes bounded programmatic tool workflows and current multi-agent
  capability, but does not make a provider beta a safe Builder OS dependency.
- [Cursor ACP](https://cursor.com/docs/cli/acp),
  [headless CLI](https://cursor.com/docs/cli/headless) and
  [subagents](https://cursor.com/docs/subagents) describe machine-readable
  session/tool boundaries. Cursor was unavailable and none was executed.
- The [MCP architecture](https://modelcontextprotocol.io/specification/2025-06-18/architecture)
  defines host/client/server isolation and capability negotiation. It is a
  connection protocol, not Builder OS packet lineage, gate or evidence policy.

**IDEATED recommendation: LIMITED SUBAGENTS, never a default workflow layer.**
Use them only for bounded, independent, post-G1 tasks with an explicit input
set, output schema, stop condition and parent. Appropriate candidates are
source comparison, targeted implementation investigation and evidence
collection. Do not delegate routing, gate approval, material design changes,
credential decisions, publishing or independent-review judgement. Never let a
subagent's build context contaminate S5.

**BUILT transport improvement:** every S4B packet now names a unique return
target under `.builderos/returns/<packet-id>.md`. The target is carried in the
manifest and prompt, verified to remain inside the project and tied to the
packet ID, and differs for every retry. `builderos.py advance` ingests only the
current packet's target. Manual response-file ingestion remains a recovery path
for providers that cannot write the target.

**READY TO PROTOTYPE, EXTERNALLY UNVERIFIED:** a future provider adapter may
drive the same verified packet and return target through Cursor ACP or a
headless session once authentication, permission prompts, cancellation and
failure recovery can be exercised. The canonical packet remains the protocol;
provider automation must not become a second workflow owner.

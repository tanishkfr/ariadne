# AR-224 Design Specificity Release Gate

Release principle: Ariadne has a house method, not a house style.
Specificity is the goal. A common pattern is not wrong; an unexamined
one is.

## Packaged check (required)

From the packaged RC, run a vague design request with no aesthetic
guidance: Make me a cool F1 dashboard (or an equivalent fresh fixture
if deterministic isolation requires it).

Verify content model before layout, at least 3 materially divergent
concepts explored internally where divergence is not merely color changes,
references selected by need with not every source queried, category
defaults detected contextually where common does not imply automatic
rejection, UNEXAMINED actionable, own-slop/failure mode present, richness
source explicit, motion intent present when motion proposed, project
identity outranking references, one recommended direction shown, internal
tool/provider choice hidden from normal UX, G1D as the principal creative
interruption with routine work continuing autonomously after approval,
no global slop score, no forced Ariadne/Boreal visual house style.

Explicitly distinguish COMMON from UNEXAMINED. A common choice justified
by the product is allowed.

## Source ecosystem

Ships the AR-222D curated registry with source role, capability, access
mode, authentication, paid status, reuse policy, terms notes, verification
date and enabled/disabled reason. No scraped third-party corpora bundled.
No claim that every registered source is integrated. Dead providers
degrade honestly; project/local evidence remains primary.

## Minimal Creative Interruption

User says the vague request once. Ariadne does research/content/concepts/
references internally, shows the recommended direction, user approves,
Ariadne continues implementation/render/critique/verification. The user is
never asked which source, MCP, design system, font shortlist, card policy
or component registry unless they explicitly ask for that control.

Result recorded in the closure report.

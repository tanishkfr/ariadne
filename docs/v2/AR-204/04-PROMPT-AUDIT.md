# AR-204 — Prompt Audit

Every static instruction was read, classified and given a reason. Two categories
came out of that: transport scaffolding, which AR-204 may rewrite behind a flag,
and stage prompt blocks, which it may not.

## 1. The two categories

The transport **scaffolding** is generated by `build_packet`: the packet header,
the transport notice, the S4B return target and worker contract, the repair
context, the conditional-omission list. The engine owns this text, its behaviour
consequence is small, and code already enforces most of what it says.

The stage **prompt blocks** in `prompts/*.md` are the behavioural instruction
sets a model reasons with. A shorter version of one of those cannot be shown
equivalent without a live model evaluation, and AR-204 runs none. They are audited
and left byte-identical in both profiles.

## 2. Transport scaffolding: the classification

| Block | Verdict | Why | Enforced by |
| --- | --- | --- | --- |
| packet title and id | KEEP | the contract and the return transport both name the packet | transport |
| provider line | MOVE | provider identity lives in the run state; only a pinned task needs it | execution identity |
| `PREPARED ONLY` status | KEEP | stops a reader mistaking a prepared packet for a finished stage | state machine |
| transport notice | REWRITE | two lines say one thing; a single line carries the instruction | — |
| Ariadne source commit | DELETE | the worker never acts on it, it is volatile, and the run records it | run-state provenance |
| parent packet | MOVE | continuation identity belongs to the transport record | manifest |
| independence boundary | KEEP | without it a reviewer asks for the project it must not have | review preconditions |
| return transport target | KEEP | the exact path is transport behaviour the worker performs | return ingestion |
| worker task contract | KEEP | the contract *is* the task | worker validation |
| lifecycle line | KEEP | the worker must know a repair is bounded before choosing to retry | repair budget policy |
| independent-validation reminder | REWRITE | the gate is code; only the "not acceptance" point is behavioural | gate preconditions, verification |
| stop-and-report instruction | KEEP | the worker must *choose* the blocked path; code can detect the result but not the choice | worker validation |
| repair context | KEEP | bounded prior-attempt evidence is what distinguishes repair from repeat | worker retry context |
| declared conditionals | KEEP | the omission record is evidence of what was deliberately withheld | context plan |

`prompting.transport_audit` performs this classification against a real packet and
measures each block's byte share, so the table is a summary of code rather than a
second home for the rule.

## 3. What was actually implemented

One profile is implemented: `compact_v2` for the scaffolding only.

* `ARIADNE source commit`, the provider line and the parent packet line are
  dropped;
* the transport notice becomes one line;
* the independent-validation reminder becomes one sentence;
* every other block is carried verbatim, and an unclassified line is untouched by
  construction.

Measured on the four real packets of the fixture: 653 bytes removed in total, or
0.49% of 134,279 rendered bytes. The saving is small and it is reported as small.
The source sections and the stage prompt block are byte-identical in both profiles
and the pack asserts that with a digest comparison.

## 4. Stage prompts: audited, not rewritten

The audit covers three of the eight prompt files — the three the fixture path
delivers — totalling 35,200 bytes, split into heading-level blocks with measured
sizes and digests. Every block in those three files classified as `KEEP`, because
their headings describe intake, context, rules, output shape and quality criteria
rather than duplicated enforcement.

`prompting.select_prompt_block(path, profile="compact_v2")` returns the original
text with `applied: false` and the reason recorded: a behavioural rewrite needs a
live evaluation that this milestone did not run. A benchmark case asserts that
refusal, which means a future attempt to ship a shorter stage prompt without
evidence fails the suite.

## 5. Code that replaced prose

Three scaffolding sentences are now redundant with enforcement:

* the pipeline statement that Ariadne validates the result independently — the
  gate refuses a boundary without a validation record;
* the instruction not to treat a worker self-report as acceptance — the acceptance
  path requires a review record and a human approval;
* the source-commit line — provenance is a run-state record and the packet is
  hashed for transport integrity.

The stop-and-report sentence is deliberately *not* in that group. Code can reject
an out-of-scope write, but only the worker can decide to stop instead of
improvising around a conflict, and that decision needs the sentence.

## 6. Reversibility

The profile is a run setting, not a build constant. `legacy` is the default, the
CLI can set and revert it per run, the configuration is recorded with a digest,
and an engine check asserts that resetting returns every behaviour-sensitive
setting to its default. A run that switches profiles keeps a record of which one
produced its packets.
